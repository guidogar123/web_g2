# Phase 2: Local SEO & Metadata Optimization - Research

**Researched:** 2026-04-03
**Domain:** Next.js 16 SEO metadata, structured data (JSON-LD), sitemap/robots generation, Open Graph image generation
**Confidence:** HIGH

## Summary

Phase 2 requires implementing a complete SEO metadata infrastructure for the G2 Intelligence Next.js 16 site. This phase heavily depends on Next.js built-in metadata APIs (generateMetadata, sitemap.ts, robots.ts, opengraph-image.tsx) combined with JSON-LD structured data injection into `<head>`. All required patterns are well-documented and directly supported by Next.js 16 without external dependencies.

**Key deliverables:**
1. Page-level metadata with geo-targeting keywords (using `generateMetadata()`)
2. LocalBusiness + Service JSON-LD schemas (injected via `<script>` in layout.tsx)
3. Automatic sitemap.xml generation (via `app/sitemap.ts`)
4. Automatic robots.txt generation (via `app/robots.ts`)
5. Dynamic OG image generation (via `app/opengraph-image.tsx` with ImageResponse)
6. Twitter Card tags (metadata object in layout.tsx)
7. Custom geo meta tags via metadata "other" field

**Primary recommendation:** Use Next.js built-in metadata APIs exclusively. No external SEO libraries needed. Inject JSON-LD schemas directly in layout.tsx, override metadata per-page in page.tsx. Use `ImageResponse` for OG/Twitter images.

## Architecture Patterns

```

├── layout.tsx              # Root layout: metadata defaults, LocalBusiness + Service JSON-LD
```

### Pattern 1: Root Metadata Defaults + Page Overrides

**What:** Define baseline metadata in `app/layout.tsx` using `export const metadata: Metadata`, then override per-page using `export async function generateMetadata()` in specific pages.

**When to use:** Every site with multiple pages that need unique titles/descriptions.

**Example:**

```typescript
// src/app/layout.tsx
import type { Metadata } from 'next';

export const metadata: Metadata = {
  title: 'G2 Intelligence — Inteligencia Artificial para Empresas en Cali y Valle del Cauca',
  description: 'G2 Intelligence ayuda a empresas a adoptar IA agentica, optimizar procesos y multiplicar ventas en Cali, Jamundí, Palmira, Yumbo.',
  metadataBase: new URL('https://g2intelligence.co'),
  openGraph: {
    title: 'G2 Intelligence — IA para Empresas en Cali',
    description: 'Transformamos empresas con inteligencia artificial en Colombia.',
    url: 'https://g2intelligence.co',
    type: 'website',
    siteName: 'G2 Intelligence',
    images: [
      {
        url: 'https://g2intelligence.co/og-image.png',
        width: 1200,
        height: 630,
        alt: 'G2 Intelligence - IA para Empresas',
      },
    ],
  },
  twitter: {
    card: 'summary_large_image',
    title: 'G2 Intelligence — IA para Empresas en Cali',
    description: 'Transformamos empresas con inteligencia artificial en Colombia.',
    images: ['https://g2intelligence.co/og-image.png'],
  },

    'geo.region': 'CO-VAC',
    'geo.placename': 'Cali, Colombia',
    'ICBM': '3.4516,-76.5320',
  },
};

// Rest of layout...
```

**Key insight:** `metadataBase` ensures all relative image URLs in openGraph and twitter are resolved to absolute URLs. This is critical for social media crawlers.

### Pattern 4: Sitemap Generation (app/sitemap.ts)

**What:** Export a default async function that returns an array of URL objects with `url`, `lastModified`, `changeFrequency`, and `priority`.

**When to use:** Site has more than a few pages; helps search engines discover all routes.

**Example:**

```typescript
// src/app/sitemap.ts
import { MetadataRoute } from 'next';

export default function sitemap(): MetadataRoute.Sitemap {
  return [
    {
      url: 'https://g2intelligence.co',
      lastModified: new Date(),
      changeFrequency: 'weekly',
      priority: 1.0,
    },
    // Add future dynamic routes here (e.g., /servicios/[slug])
  ];
}
```

**Key insight:** Next.js automatically serves this at `/sitemap.xml`. The XML serialization, namespaces, and proper formatting are handled automatically. No manual XML writing needed.

### Pattern 5: Robots.txt Generation (app/robots.ts)

**What:** Export a default function that returns a `MetadataRoute.Robots` object with rules and sitemaps array.

**When to use:** All sites should have a robots.txt; tells crawlers what's allowed and where the sitemap is.

**Example:**

```typescript
// src/app/robots.ts
import { MetadataRoute } from 'next';

export default function robots(): MetadataRoute.Robots {
  return {
    rules: {
      userAgent: '*',
      allow: '/',
      disallow: ['/api/', '/admin/'], // Add disallowed paths if needed
    },
    sitemap: 'https://g2intelligence.co/sitemap.xml',
  };
}
```

**Key insight:** Next.js automatically serves this at `/robots.txt`. Default is allow all (`allow: '/'`); only add disallow paths if you have protected routes.

### Pattern 7: Custom Geo Meta Tags via "other" Field

**What:** Add non-standard meta tags (geo.region, geo.placename, ICBM) using the `other` field in Metadata object.

**When to use:** SEO for location-specific sites; improves geo-targeting signals.

**Example:**

```typescript
// In generateMetadata() or layout.tsx metadata export:
export const metadata: Metadata = {
  title: '...',
  other: {
    'geo.region': 'CO-VAC', // Colombia, Valle del Cauca
    'geo.placename': 'Cali, Colombia',
    'ICBM': '3.4516,-76.5320', // Cali coordinates
  },
};
```

**Key insight:** The `other` field accepts an object where keys become meta tag `name` attributes and values become `content` attributes. This is the mechanism for any custom meta tag not directly supported by Next.js Metadata type.

### Anti-Patterns to Avoid

- **Anti-pattern: Hardcoded metadata in each page component.** Result: Duplicated boilerplate, inconsistent sitewide changes difficult. Instead: Use layout.tsx defaults + generateMetadata overrides.

- **Anti-pattern: Using external SEO libraries (next-seo, next-sitemap).** Result: Added dependencies, version conflicts, outdated APIs. Instead: Use Next.js 16 built-in metadata APIs exclusively.

- **Anti-pattern: Serving static OG images only.** Result: No personalization, same image for all pages. Instead: Use ImageResponse for branded, dynamic OG images per route.

- **Anti-pattern: Injecting JSON-LD in page.tsx instead of layout.tsx.** Result: Schema duplicated on every page, bloated HTML. Instead: Inject LocalBusiness + Services schemas once in root layout.tsx.

- **Anti-pattern: Forgetting metadataBase or using relative URLs for OG images.** Result: Social media crawlers fail to find images, broken previews. Instead: Set metadataBase and use absolute URLs for all OG/Twitter images.

- **Anti-pattern: Including grid layout in ImageResponse.** Result: Build fails silently or image renders incorrectly. Instead: Use flexbox only; simulate grid with multiple flex containers.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Metadata management | Manual title/description per page | Next.js `generateMetadata()` + layout.tsx defaults | Framework handles cascading, merging, defaults automatically; zero bugs |
| Sitemap XML generation | Custom XML serialization | Next.js `app/sitemap.ts` with MetadataRoute.Sitemap | Next.js handles namespace, priority ordering, XML escaping; bug-free format |
| Robots.txt generation | Manual robots.txt text file | Next.js `app/robots.ts` with MetadataRoute.Robots | Ensures correct format; auto-includes sitemap URL; no typos |
| OG image generation | Photoshop exports + CDN | ImageResponse from `next/og` | Dynamic, branded, cacheable; scales to all routes without manual work |
| Social media meta tag management | Separate og: and twitter: objects per page | Metadata `openGraph` and `twitter` fields | Single source of truth; Next.js merges into correct HTML; no duplication |
| JSON-LD schema validation | Manual schema-dts types | schema-dts npm package (optional) + TypeScript checking | Validates schema at build time; catches missing required fields |

**Key insight:** Next.js's metadata system is designed to prevent the most common pitfalls: missing metadataBase (broken OG images), duplicated schemas, inconsistent defaults. Use the framework; it's more reliable than custom code.

## Common Pitfalls

### Pitfall 1: Forgetting `metadataBase` Breaks Social Media Crawlers

**What goes wrong:** OG images specified as relative paths (`/og-image.png`) are not resolved to absolute URLs. Social media crawlers (Facebook, Twitter, LinkedIn) fetch from the public internet and fail to find `/og-image.png` relative to their domain.

**Why it happens:** Developers assume "the site knows its own domain" — but OG crawlers are external. They see `/` as their root, not your site's domain.

**How to avoid:** Always set `metadataBase` in root layout.tsx:
```typescript
export const metadata: Metadata = {
  metadataBase: new URL('https://g2intelligence.co'),
  openGraph: {
    images: ['/og-image.png'], // Automatically becomes https://g2intelligence.co/og-image.png
  },
};
```

**Warning signs:** OG preview in Twitter/Facebook tester shows broken image icon; Chrome DevTools shows `og:image` meta tag with path instead of absolute URL.

### Pitfall 2: ImageResponse with Grid Layout Fails Silently

**What goes wrong:** Developer uses `display: grid` in ImageResponse JSX. Build succeeds, but image renders as blank or distorted PNG.

**Why it happens:** ImageResponse uses Satori (HTML→PNG renderer) which only supports flexbox. Grid is parsed but ignored at runtime.

**How to avoid:** Use `display: flex` exclusively. Simulate grid with nested flex containers:
```typescript
// DON'T:
<div style={{ display: 'grid', gridTemplateColumns: '1fr 1fr' }}>

// DO:
<div style={{ display: 'flex', flexDirection: 'row', gap: '20px' }}>
  <div style={{ flex: 1 }}> {/* flex: 1 = 50% width */}
```

**Warning signs:** Image appears blank or text is misaligned; you're using CSS Grid properties.

### Pitfall 3: JSON-LD XSS if User Input Not Sanitized

**What goes wrong:** User-generated data (e.g., service description from admin panel) is injected directly into JSON-LD without escaping. A malicious `<script>` tag in the data breaks the script tag context.

**Why it happens:** `dangerouslySetInnerHTML` skips React escaping. `JSON.stringify` does not HTML-escape; it only escapes JSON special characters.

**How to avoid:** For hardcoded schemas (Phase 2), no risk — schemas are in source code. For user-generated content, sanitize before JSON.stringify:
```typescript
// Safe: hardcoded schema
JSON.stringify(localBusinessSchema) // OK

// Risky: user data without sanitization
const userSchema = { description: unsafeUserInput };
JSON.stringify(userSchema) // NOT OK if userInput contains <

// Safe: user data with sanitization
const sanitized = unsafeUserInput.replace(/</g, '\\u003c');
JSON.stringify({ description: sanitized }) // OK
```

**Warning signs:** Admin submits a service description with angle brackets; HTML renders unexpectedly or console shows JSON syntax errors.

### Pitfall 4: Metadata Not Merging / Cascading from Layout to Page

**What goes wrong:** Developer sets metadata in `layout.tsx` and `page.tsx`, expects both to merge. Instead, page metadata completely overrides layout metadata.

**Why it happens:** Misunderstanding of Next.js metadata merging rules. Layout metadata does NOT automatically merge with page metadata; page exports completely replace layout exports.

**How to avoid:** In `page.tsx`, import and spread layout metadata, then override specific fields:
```typescript
// src/app/page.tsx
import { metadata as layoutMetadata } from './layout';

export const metadata: Metadata = {
  ...layoutMetadata,
  title: 'Home — IA para Ventas en Cali', // Override only title
  // openGraph, twitter, etc. cascade from layout
};
```

Alternatively, rely on `layout.tsx` defaults and ONLY use `generateMetadata()` for page-specific overrides — don't mix.

**Warning signs:** OG image, description, or other fields from layout.tsx disappear on home page; only explicitly set fields appear in HTML.

### Pitfall 5: Sitemap Routes Not Indexable Because Missing Explicit Entries

**What goes wrong:** Team assumes sitemap.ts auto-discovers all routes. Only the root `/` is listed in sitemap.xml; future dynamic routes (`/servicios/[slug]`) are missing.

**Why it happens:** Confusion between static file discovery and explicit route listing. Sitemap must be manually maintained or fetched from a data source.

**How to avoid:** Explicitly list all routes in sitemap.ts, or fetch from a database:
```typescript
export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  const baseUrls = [
    { url: 'https://g2intelligence.co', lastModified: new Date(), priority: 1.0 },
  ];

  // For future dynamic routes:
  // const services = await getServices();
  // const serviceUrls = services.map(s => ({
  //   url: `https://g2intelligence.co/servicios/${s.slug}`,
  //   lastModified: s.updatedAt,
  //   priority: 0.8,
  // }));
  // return [...baseUrls, ...serviceUrls];

  return baseUrls;
}
```

**Warning signs:** sitemap.xml shows only `/` and no other routes; Google Search Console reports "submitted URL not found in sitemap."

### Pitfall 6: og:image Size Mismatch or Wrong Format

**What goes wrong:** OG image is 600x315 instead of 1200x630. Social media cropping is inconsistent, image appears distorted.

**Why it happens:** Assumption that any size works. Different platforms (Facebook, Twitter, LinkedIn) have different optimal sizes.

**How to avoid:** Always generate 1200x630. Set size in both ImageResponse export and metadata:
```typescript
export const size = { width: 1200, height: 630 };

export const metadata: Metadata = {
  openGraph: {
    images: [{ url: '/og-image.png', width: 1200, height: 630, alt: '...' }],
  },
};
```

**Warning signs:** Twitter preview shows image at 2:1 aspect ratio instead of expected size; image is cropped oddly on LinkedIn.

## State of the Art

| Old Approach | Current Approach | When Changed | Impact |
|--------------|------------------|--------------|--------|
| Static metadata export (no dynamism) | `generateMetadata()` async function | Next.js 13.2+ | Enabled per-page SEO, dynamic OG images, route-aware metadata |
| External libraries (next-seo, next-sitemap) | Built-in Next.js APIs (app/sitemap.ts, app/robots.ts) | Next.js 13+ | Eliminated dependencies, reduced bundle size, single source of truth |
| Manual XML sitemap files | `app/sitemap.ts` route handler | Next.js 13+ | Automatic XML generation, automatic type safety, integrates with metadata system |
| Static PNG for OG images (Figma export) | `ImageResponse` from next/og | Next.js 13.5+ | Dynamic, branded, per-route images; zero manual work scaling to hundreds of pages |
| Hardcoded metadata in HTML | Metadata API cascading system | Next.js 13.2+ | Layout defaults + per-page overrides = DRY, maintainable, merge-safe |

**Deprecated/outdated in Phase 2 scope:**
- `next-seo` package: Next.js 16 built-in metadata supersedes it
- Manual robots.txt text files: `app/robots.ts` is the standard now
- next-sitemap npm package: Use `app/sitemap.ts` instead

## Open Questions

1. **Service schema detail level (Claude's discretion):**
   - Should each Service include `offers` (pricing) or `serviceArea` (additional geographic data)?
   - Current plan: Use minimal schema (name, description, provider) to pass Rich Results Test
   - Recommendation: Start minimal; can enhance in Phase 3 if needed

2. **Single JSON-LD block vs. multiple blocks:**
   - Should LocalBusiness and Services be in one combined script or separate scripts?
   - Current plan: Separate scripts (LocalBusiness in one, Services ItemList in another)
   - Reason: Clearer, easier to update per-schema type

3. **OG image text styling (Claude's discretion):**
   - Should the OG image include a logo, or text-only design?
   - Current recommendation: Text-only (Void Black background + Emerald text) — simpler, brand-aligned, works on any platform
   - Logo adds complexity and requires asset management

4. **Keyword stuffing vs. natural language:**
   - How much geo-targeting is too much in title/description?
   - Example: "G2 Intelligence — IA para Empresas en Cali, Jamundí, Palmira, Yumbo" vs. "G2 Intelligence — IA para Empresas en Cali"
   - Recommendation: Keep it natural. Include primary city only in title; let LocalBusiness schema handle full area served.

## Environment Availability

No external dependencies required for core functionality. All Next.js metadata APIs are built-in to Next.js 16.2.2 (installed in sitio-g2-nextjs/package.json).

| Dependency | Required By | Available | Version | Fallback |
|------------|------------|-----------|---------|----------|
| Next.js | All SEO features | ✓ | 16.2.2 | N/A |
| `next/og` | OG image generation | ✓ | Built-in to Next.js 16 | N/A |
| ImageResponse | Dynamic image rendering | ✓ | @vercel/og (via Next.js) | Static PNG file in `/public` |
| TypeScript | Optional typing (schema-dts) | ✓ | 5.x installed | Use untyped objects (JSON) |

**Missing dependencies with fallback:**
- Custom fonts in ImageResponse: ImageResponse can use system fonts (Arial, sans-serif) or load via `fetch()` — no font library needed.
